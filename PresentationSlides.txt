SLIDE 3 — PROBLEM STATEMENT
================================================================================

  THE PROBLEM:
  Book lovers often accumulate books they have already read, while struggling
  to find affordable access to new titles. Traditional methods of exchanging
  books — such as local libraries, second-hand stores, or informal sharing —
  are limited by geography, lack of trust, and poor communication channels.

  WHY THIS PROJECT IS NEEDED:
  • No dedicated online platform exists for peer-to-peer book lending & selling
    within a trusted community.
  • Readers lack a way to discover books available nearby and connect directly
    with owners for exchange.
  • There is no built-in trust mechanism (ratings/reviews) or real-time
    communication to coordinate exchanges safely.
  • Physical bookstores and e-commerce platforms do not support a
    lend-and-return model, leading to book hoarding and waste.

  OUR SOLUTION:
  A full-stack MERN web application that creates a vibrant community platform
  where book lovers can lend, sell, and discover books — with secure
  authentication, real-time chat, and a reputation system.


================================================================================
SLIDE 4 — OBJECTIVES
================================================================================

  MAIN GOALS:
  1. Build a secure, scalable community platform for peer-to-peer book exchange.
  2. Enable users to list books for lending (free) or selling (priced).
  3. Implement a multi-step transaction workflow with real-time status tracking.
  4. Provide instant in-app chat between exchange partners using WebSockets.
  5. Establish trust through a two-way user rating and review system.

  KEY FEATURES TO BE IMPLEMENTED:
  • JWT-based secure authentication (Register / Login)
  • Full CRUD operations for book listings with image uploads
  • Advanced transaction lifecycle: Request → Accept → Send → Receive → Complete
  • Real-time chat via Socket.IO for exchange coordination
  • User profiles with 5-star ratings and review history
  • Personal dashboards: My Books, Requests, Wishlist, Profile
  • Dark/Light theme toggle with OS-preference detection
  • Responsive design across desktop, tablet, and mobile

  EXPECTED OUTCOMES:
  • A fully functional, production-ready web application
  • Seamless user experience with modern animations and theming
  • Secure data handling with encrypted passwords and token-based auth

SLIDE 7 — SYSTEM ARCHITECTURE
================================================================================

  ARCHITECTURE: Three-Tier MERN Stack (Client–Server–Database)

  ┌─────────────────────────────────────────────────────────────────────┐
  │                        CLIENT (Browser)                            │
  │  ┌───────────────────────────────────────────────────────────────┐  │
  │  │  React 19 SPA  •  Bootstrap 5  •  Framer Motion              │  │
  │  │  React Router (Pages)  •  Socket.IO Client (Chat)            │  │
  │  └──────────────────────────┬────────────────────────────────────┘  │
  │                             │  HTTP REST API  +  WebSocket         │
  │                             ▼                                      │
  │  ┌───────────────────────────────────────────────────────────────┐  │
  │  │              SERVER (Node.js + Express.js)                    │  │
  │  │  Auth Routes  •  Book Routes  •  Request Routes               │  │
  │  │  User Routes  •  Message Routes  •  Wishlist Routes           │  │
  │  │  JWT Middleware  •  Multer Uploads  •  Socket.IO Server       │  │
  │  └──────────────────────────┬────────────────────────────────────┘  │
  │                             │  Mongoose ODM                        │
  │                             ▼                                      │
  │  ┌───────────────────────────────────────────────────────────────┐  │
  │  │              DATABASE (MongoDB — bookExchangeDB)              │  │
  │  │  Users  •  Books  •  Requests  •  Messages  •  Conversations  │  │
  │  └───────────────────────────────────────────────────────────────┘  │
  └─────────────────────────────────────────────────────────────────────┘

  CLIENT-SERVER INTERACTION:
  • React frontend sends HTTP requests (GET, POST, PUT, DELETE) to
    Express REST API endpoints on port 5000.
  • JWT tokens are sent in the Authorization header for authenticated routes.
  • Socket.IO maintains a persistent WebSocket connection for real-time chat.
  • Multer handles multipart/form-data for image uploads.
  • Mongoose translates JavaScript objects to MongoDB documents.

SLIDE 9 — MODULES OF THE PROJECT
================================================================================

  MODULE 1: USER AUTHENTICATION & REGISTRATION
  • Secure signup with email validation and bcrypt password hashing
  • JWT-based login with token stored in localStorage
  • Protected API routes via auth middleware

  MODULE 2: BOOK CATALOG & LISTING MANAGEMENT (CRUD)
  • Add, edit, delete book listings with image upload (Multer)
  • Book types: Lend (free) or Sell (priced)
  • Status tracking: Available → Pending → Exchanged

  MODULE 3: BOOK EXCHANGE TRANSACTION WORKFLOW
  • Multi-step lifecycle: Request → Accept → Ship → Receive → Complete
  • Automatic book status update on transaction completion

  MODULE 4: REAL-TIME IN-APP CHAT
  • Socket.IO WebSocket-based private messaging
  • Auto-created chat room upon request acceptance
  • Message history persisted in MongoDB

  MODULE 5: USER PROFILES, RATINGS & REVIEWS
  • Profile pages with personal info and profile picture upload
  • 5-star rating system with comments after transaction completion
  • Dynamic average rating calculation

  MODULE 6: PERSONAL DASHBOARDS & WISHLIST
  • My Books — manage own listings
  • Requests — track incoming/outgoing exchange requests
  • Wishlist — save favorite books for later
  • Stats Bar — view personal statistics

SLIDE 11 — DATABASE DESIGN
================================================================================

  DATABASE: MongoDB (NoSQL) — bookExchangeDB
  ODM: Mongoose 8

  COLLECTIONS & RELATIONSHIPS (ER OVERVIEW):

  ┌──────────────┐       ┌──────────────┐       ┌──────────────┐
  │   USERS      │       │    BOOKS     │       │   REQUESTS   │
  ├──────────────┤       ├──────────────┤       ├──────────────┤
  │ _id          │◄──┐   │ _id          │◄──┐   │ _id          │
  │ email        │   │   │ title        │   │   │ book ────────┼──► Books._id
  │ password     │   │   │ author       │   │   │ requester ───┼──► Users._id
  │ firstName    │   │   │ description  │   │   │ owner ───────┼──► Users._id
  │ lastName     │   ├───┤ owner ───────┤   │   │ status       │
  │ city         │   │   │ type (L/S)   │   │   │ createdAt    │
  │ state        │   │   │ price        │   │   │ updatedAt    │
  │ profilePic   │   │   │ condition    │   │   └──────────────┘
  │ ratings[]    │   │   │ bookCover    │   │
  │ avgRating    │   │   │ status       │   │   ┌──────────────────┐
  │ createdAt    │   │   │ createdAt    │   │   │ CONVERSATIONS    │
  └──────────────┘   │   └──────────────┘   │   ├──────────────────┤
                     │                      │   │ _id              │
                     │                      │   │ participants[] ──┼──► Users._id
                     │                      │   │ request ─────────┼──► Requests._id
                     │   ┌──────────────┐   │   │ messages[]       │
                     │   │  MESSAGES    │   │   │ createdAt        │
                     │   ├──────────────┤   │   └──────────────────┘
                     │   │ _id          │   │
                     └───┤ sender ──────┤   │
                         │ conversation ┼───┘
                         │ text         │
                         │ createdAt    │
                         └──────────────┘

  KEY RELATIONSHIPS:
  • A User owns many Books (one-to-many)
  • A Request links a Book, a Requester (User), and an Owner (User)
  • A Conversation references two Users (participants) and one Request
  • Messages belong to a Conversation and have a sender (User)
  • Ratings are embedded as sub-documents inside the User document
